# Host-assisted compact context development trial

On October 5, 2026, a frozen trial compared ordinary lexical context with the existing host-selection workflow on source commit `ceaed2c624aca583d034c880f1bc43ed1a28e7ae`. Independent Astra assessment scored the assisted workflow **9.5/10 but failed mandatory completeness**. It completed 11/12 strict scheduled tasks, compared with 3/12 for automatic context. This is development evidence for an assisted workflow, not native HIGH, generated answers or vault-capacity acceptance.

## What was compared

Four newly captured, licensed public Markdown snapshots of Python argparse/unittest and Git reset/revert documentation supplied 238,115 UTF-8 bytes. Five positive questions and one absent-information question were independently frozen before outputs. Two positive questions were repeated after a formatting-only SourceRevision refresh, Source withdrawal and complete-cache-loss reconstruction, giving 12 scheduled slots. Expected facts stayed with the critic; labels were never indexed.

Both branches used the same Source revisions, index state and output limits: lexical indexed-documents, five owners, 80 candidates, 1,024-byte excerpts, 6,000 rendered bytes and 1,500 estimated tokens; selected proof 64 MiB / 4,096 files / 65,536 entries / 5 seconds. The assisted branch exported the public preparation packet, delivered only its exact selector input to a fresh `gpt-6.1-sol` actor, applied its raw fingerprint-bound ID reply, and inspected every returned citation through verified reads. No new embeddings, provider generation API, deck expansion, model retry or product tuning occurred.

The missing paragraph was available in the displayed deck and was not selected; no later packing stage discarded it. The failure remains in the denominator. Citation correctness does not erase incomplete evidence.

## Correctness and operational observations

All 12 raw replies were admitted. Independent checks found 68 returned passage occurrences matching original source bytes, exact interval/hash citations, and no integrity blocker. Six old-reply replays failed with freshness conflict after refresh, withdrawal or rebuild. Earlier retained revisions remained readable with Historical/Withdrawn scope. Refresh converted LF to CRLF only: it tested revision binding and stale-reply handling, not adaptation to changed factual content.

Complete backup and restored inventories matched before cache deletion. Public offline normalized rebuild and full check preserved 79 noncache canonical, immutable and retained-history files with exact bytes and mtimes. Only the operation-publication pointer and writer-lock metadata were narrow, recorded exceptions. The original vault and backup remained unchanged. Public initialization uses schema1 storage; normalized indexing is independent of explicit retained-storage migration.

Two supervisor attempts failed on guessed output/layout assumptions and remain recorded. Their continuations preserved the original clock, counters and completed slots, with independent prospective reviews. A third version was vetoed before execution because its operation-revision guard contradicted the actual rebuild transition. The corrected fourth supervisor completed the remaining work; these are harness outcomes, not product defects or discarded failed attempts.

Exact one-file delivery and raw replies were audited from each assigned actor's scoped local rollout; known transport stayed within 1,024 bytes. ## Repeating or adapting the workflow

Use a disposable initialized normalized vault, capture the chosen immutable corpus through ordinary commands, then follow the preparation/replay interface in [indexed context](indexed-context.md). Freeze task expectations, executable, corpus hashes, budgets and the actor's complete inputs before opening candidate outputs. Compare automatic and assisted context against the same publication; inspect returned evidence rather than source-hit rates. Count each inference request and observed usage separately from native work. Any questions used to guide a future fix are development data; a new solution needs separate acceptance questions.

This bounded trial is closed as **failed mandatory completeness**. It supports investigating host selection, but does not qualify it as complete or establish a new deterministic retrieval solution. Native HIGH, full normalized query parity and representative 25k / approximately 2.5 GB qualification remain open.
