# P18 API extraction implementation plan

Bounded library inputs: `ApiExtractionRequest { export: ExportRequest, run_id: RecordId, created_at_utc_ms: i64, deadline_utc_ms: i64, limits: LifetimeLimits, max_output_tokens: u64, new_extraction: bool }`; entry `OfflineApp::graph_extract_api(&request, &TrustedService, &Dispatcher, JobOptions) -> Result<ApiExtractionOutcome>`. No ambient provider config or credentials. Root shared wiring must export `graph::{api_extract,generation_cache}` and build those explicit values. CLI needs executor api/profile/provider config/run ID (resume existing run)/request byte-token-money/deadline limits/output token ceiling. API rejects dry-run/offline/stage-only before packet/job writes; root may handle dry-run by existing packet plan only.

Immutable packet export calls exact existing `graph_extract_agent`; reload it with `SourceView`/`packet::load_packet`. Canonical RemoteInput separates packet instructions and canonical packet data, retains exact output schema. `wire::task_fingerprints` + `jobs::tasks::task_key` bind prompt+schema+model/revision+settings+complete packet/context; descriptor retained under restricted state input. Source/packet dependencies are reused unchanged. Bootstrap/create/checkpoint/applyCatalog use existing production engine and JobLedger.

Generation result must pass the exact P10 `wire::validate_response` before proposal staging. Successful response retained as immutable Markdown generation output (run_event record) plus actual usage receipt in one `checkpoint::receipt_plan` changeset, then `outputs_committed`, crate-private `settle`, checkpoint. The retained output is separate from extraction proposals: staging calls exact `import::stage_import` and returns its PreparedChange for explicit changes apply; never resolve/review/accept. This allows accounting/output durability without implicitly applying proposal changesets. Cache is only an index/reuse aid; canonical Markdown output and receipts are authoritative. Resume uses actual spool hashes and paid strict generation decoder before settlement; prior outputs are reimported through importer origins preserving durable IDs and decisions.

Root additions requested: production Dispatcher method `recover_response(ledger, service, task, attempt) -> Result<DispatchOutcome, Box<DispatchFailure>>` that verifies actual stored spool hashes/metadata/task and uses existing sealed prepare/decode path without network, and returns rejected materialization for paid malformed output; or grant worker leaf implementation a crate-private helper in dispatcher. Current public execute refuses an unmaterialized prior response; no public decoder/recovery path exists. Prefer root owns this small method. Existing crate-private checkpoint receipt_plan and DispatcherLedgerApi suffice for production settlement; no fake accessors needed.

Tests use disposable fixtures and mock Transport routed through real production encoder/decoder (external integration tests), exercise same importer lifecycle, decision preservation, changed task identity, malformed/refused/truncated charged output, paid spool recovery, cancellation unknown, no implicit identity/review. No live qualification claim. Root serializes Cargo grants.
