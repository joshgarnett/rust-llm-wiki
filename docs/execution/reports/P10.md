## Implemented behavior

- `packet::build_packet` returns an exact immutable task and guarded changeset draft, or an existing persisted packet/locator. Packet fields include full static extraction output schema, fixed instructions/versioned registry, exact source/revision snapshot hash, UTF-8 byte windows and heading context, effective limits and bounded optional canonical entity context. Canonical JSON explicitly sorts every object's keys through BTreeMap, preserves array order and hashes all task fields except packet ID/fingerprint. Packet ID derives deterministically from its BLAKE3 fingerprint; timestamps remain note metadata.
- Omitted windows segment exact source bytes deterministically at newline/UTF-8 boundaries, at most16x12000 bytes. Coverage reports unselected bytes. Explicit windows must be nonempty, sorted, disjoint and bounded. Oversized requests reject before source reads or window cloning. Exported candidate data must equal actual same-vault canonical entity context; persisted candidates remain saved context snapshots, so a later entity title change neither binds mentions nor corrupts a restored task.
- `packet::load_packet` selects exactly one actual Markdown fenced block with info `lwiki-extraction-packet-v1`, validates the supported output schema/registry, derived fingerprint/ID, envelope/body identity and full snapshot/source ownership. Nested candidate RecordRef unknown fields are explicitly rejected. A false HTML/comment fence cannot provide artifact authority; duplicate/unclosed/contained artifact fences refuse. Root application code must persist/apply the draft before packet stdout; the leaf returns no dispatch authority and launches no agent.
- `wire::validate_response` accepts one bounded raw JSON object with strict nested DTOs and recursive duplicate-key rejection through the existing production strict_json helper. It rejects null optional values, noninteger JSON numbers, unknown fields/schema versions, duplicate local IDs, missing local/window references and out-of-registry qualifiers/predicates/literals. Canonical proposition validation is reused with synthetic validation-only endpoint IDs; no synthetic records are written. Each mention/evidence quotation needs a unique exact window match or an explicit exact absolute UTF-8 span. Unresolved quotations must occur in their window but grant no citation.
- `import::stage_import` first validates held root binding and original read guards. Canonical extraction matches and retained origin keys precede all ID allocation. `prepare_or_reuse` generates extraction/assertion/evidence IDs only inside build_once; exact raw response bytes/hash, verified source proofs, complete Pending mention mappings and immutable reserved allocations are retained in the readable extraction note/fenced `lwiki-extraction-state-v1` artifact and change manifest. Import creates no global entity or unbound canonical assertion/evidence. Facts remain source-local proposals for explicit P11 resolution.
- Identical staged/completed responses reuse IDs; other raw responses conflict unless `AllowNewResponse` was explicit. Canonical-only Markdown restoration returns `CanonicalRestored`, no invented PreparedChange/status and the current canonical locator. Same-response reuse preserves explicit Resolved/Rejected bindings and later materialized record statuses. Canonical and retained artifacts must match every immutable identity/raw/proof/allocation field; bindings/materialized membership may evolve. Manifest allocated IDs and retained proposed envelope are also verified before reuse.
- `load_extraction` supplies sealed validated restoration for P11. It checks exact envelope/source/packet/raw response/hash/proof/map/cardinality/order/unique-ID identity, complete bindings, explicit active decision provenance, materialized endpoints/propositions/qualifiers and original reserved evidence traces. Original evidence may remain active historical, later be retracted, or have successor evidence; its reserved ID/proof is not rewritten. Accepted/rejected authored assertions retain their statuses. `artifact_body` provides the shared readable body renderer for later guarded updates.

## Bounds and guards

Packet/artifact serialized JSON2MiB; raw response256KiB; JSON depth32 and nodes65536; mentions64/assertions128; evidence16/assertion and512total; unresolved128; candidates32; headings16/window and1024bytes/heading; labels/candidate titles1024bytes; descriptions/reasons4096bytes; instructions16384bytes; property1024/unit256bytes. Actual serialized lengths account for JSON escaping. Schema and task strings are bounded without truncation. Raw-response restoration applies its separate256KiB limit rather than a generic short-string limit. Tree depth/item checks follow duplicate-safe parsing of an already byte-bounded input; they are semantic tree limits, not streaming allocation counters or a total-operation memory guarantee.

Production importer builds a bounded SourceView (64MiB canonical aggregate/4096files) and uses revision_content_bounded with independent64MiB original/content caps before allocation, full hashes and revision ownership. Packet and subsequently observed source dependencies are merged with conflict detection rather than overwriting old observations. Guards survive preparation/application through retained `read_preconditions`. Restoration no longer calls the legacy unbounded citation verifier after bounded snapshot verification: it uses exact typed companion/trace checks and root-exposed shared `note_quote` decoding, avoiding a second unbounded asset fallback. Hash checks do not provide external-editor compare-and-swap.
