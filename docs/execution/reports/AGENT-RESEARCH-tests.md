# Agent research handoff integration coverage

`tests/research_handoff.rs` uses disposable `WIKI.md` vaults and the public research library. No provider configuration, credentials, network service or live vault is used.

The cases cover a persisted `collect_sources` packet, agent-reported inline source capture, an answer citing the returned passage ID, unassessed final claims, and exact retry reuse of source/revision IDs and counters. A changed submission for a consumed packet conflicts. A consumed collection retried after its source refresh while an Answer packet is outstanding returns a stale historical result without packet/import authority; explicit refresh produces a new Answer packet. A completed-run retry after another refresh retains the completed report. An answer that resolves an earlier collection gap has an empty final gap list and a nonpartial report.

Freshness coverage changes an existing source after packet creation, requires explicit `resume --refresh`, rejects the old packet, and removes withdrawn-source passages from the refreshed packet. Protocol negatives include a foreign vault packet, wrong fingerprint, unknown JSON field, duplicate JSON key, oversized JSON/source input, quote-hash-shaped and invented passage IDs. Rejected non-dry submissions are checked against the disposable file tree's hashes and modification times, excluding only `.wiki/state/writer.lock`, whose mtime legitimately changes during guarded admission. Dry-run uses a full-tree comparison with a fresh snapshot immediately before the call. `research plan`, dry-run start/import, an offline app given an online scope, and offline tasks are checked for no writes or external acquisition task. Follow-up rounds survive reopening the app; identical partial answer reports across two continuing rounds exercise distinct durable generations.

The worker ran `rustfmt --edition 2024 tests/research_handoff.rs` and `git diff --check`. No Cargo/Bazel tests were run by this worker; the root owns compilation, execution, and integration results.
