## Retrieval patch independent review

Reviewed the query-aware lexical selector, SourceMap binary lookup, fusion/application wiring, and context default of 1024 bytes versus search 240. No consequential source defect found: focusing validates the winning embedding unit's source span, parses within that span, clamps the selected window, and derives text/hash from the original UTF-8 slice. Existing verified-snapshot/eligibility citation guards remain; identity-only entities bypass description focusing. Fixed-point per-window scores avoid cumulative floating-point ties; all source tokens are considered before the returned match cap. The window heuristic is bounded around matched tokens, not an exhaustive semantic entailment selector. No corpus or language-specific stopword list was introduced.

Added three direct unit regressions in the leased test-only tail of `src/retrieval/fusion.rs`: stronger matches outside a winning unit versus a late inside cluster; Unicode span/hash/SourceView verification and no-match/invalid-boundary cases; unverified/stale sources and unsupported identity descriptions never acquiring source citations. Initial root compilation exposed a missing test-only CitationScope import, corrected. Root’s final `focused-unit-cases.log` confirms all three new retrieval tests and the diagnostic-redaction test passed (four tests; 142 filtered out).

A material comparison confound was found: original lexical evaluation used generation 39 and the after run generation 87. Old code on generation 87 reproduces the changed rankings for q01/q06/q16 (`paired-rank-probe.json`, read-only `--no-sync`). The ranking movement cannot be attributed to excerpt selection. The completed paired old-binary baseline on the unchanged generation 87 snapshot reproduces all 72 top-five path lists across the three modes (`paired-rank-full.json`). Paired lexical hit@5=1.0 and MRR=.755303; semantic hit@5=1.0 and MRR=.916667, unchanged. Mean context source recall fell with larger windows: lexical 1.0 to .90909 and semantic .98485 to .93939. Larger excerpts trade source diversity for surrounding text. Immutable source content and unchanged query hashes alone do not control global FTS statistics.

Claim scope: expected-source hit@5 is source discovery, not answer completeness; exact citation checks prove quoted bytes, not entailment. The 24 agent-labeled questions include 22 answerable and 2 absent facts; the latter require separate interpretation. Cached offline after-run latency cannot establish a speedup against a baseline that paid for live query embedding. Corpus relevance labels are not exhaustive human judgments, and snippets were tuned after inspecting this set: the rerun is a regression comparison, not a held-out quality benchmark.

## Held-out semantic outcome and residual quality limits

The frozen eight-question semantic run returned every expected source for the six answerable questions (hit@1 and mean source recall both 1.0). Independent reading of actual context, scored against the prewritten reasons, found **1 usable, 3 partial, and 2 not useful**. h04 contains the read-only WAL conditions and DELETE recommendation; h01 loses the NO_COLOR value and animation rules; h05 cuts before failed-write recovery guidance; h06 omits the title improvement. h02/h03 lack the requested panic configuration and ignored-test commands. The two absent facts remain unsupported by neighboring SQLite/tutorial passages; nonempty retrieval is not an abstention test. No generated answer was evaluated.

The critic independently checked all 40 returned semantic source citations: original UTF-8 bytes, span equality, revision/source locator identity, and BLAKE3 quote hashes match. Per-question judgments and response hashes are in `.artifacts/ux-critic/heldout-review.json`, reproduced by `heldout-review.py`. Citation integrity does not change the low answer-completeness result.

The first held-out run hit the default 16384 verification-entry ceiling at h06 after additional query records enlarged the vault. It returned BUDGET_EXCEEDED and no context, correctly withholding verification. Root retained original outputs in `evaluation-heldout-initial`, completed only the two remaining live query calls, and reran all eight with cached offline queries and an explicit 65536 entry allowance. Final scoring uses that changed protocol: context 6,000 bytes / 1,500 estimated tokens, limit 5, candidates 80, default 1,024-byte excerpt allowance. Successful held-out completion must not be represented as success under unmodified verification defaults or as eight additional calls on the final cached rerun.

Scoped recovery improvement: `verification.rs` now adds closed, resource-specific hints naming the relevant verification flag. Limits, admission, deadline checks, and retryability remain unchanged. Existing freshness tests now require the correct hint for all four exhausted resources, still require failure, and then verify successful context after explicitly restoring sufficient bounds. Root’s `final-continuation.log` confirms the context_freshness target passed, including all four hint checks; `context-final.log` confirms the context CLI target passed. Directory/component checks can repeatedly scan shared ancestors; the 16,384 entries are logical work, not a unique-file count. A separate scalability design would need to preserve nested-vault/symlink/freshness checks.

Read-only cache diagnosis (`heldout-failure-diagnosis.json`) separates two failure types. h02 selected the metadata unit 0..441 and backtrace unit 5881..8580; the desired unwinding/configuration facts are in a different eligible unit 441..3091. Query-aware focusing correctly cannot leave the selected units, so this is a dense unit-selection/content-packaging limitation. h03 selected a unit 5771..8535 containing the required commands at 8004 and8501, but term-overlap scoring chose 6254..6766. This is a deterministic heuristic-quality failure: shared question vocabulary can outweigh the requested identifiers, and the two complete commands span more than the 512-byte primary allowance after splitting 1,024 between two excerpts. No source-span, identity, stale-citation, or score-ordering correctness violation was found in these cases.

Residual severity: P2 answer-context usability. Search is useful for locating source documents; users should inspect the full captured source before asserting specific procedural answers. The patch improves selected development examples, but neither the in-sample 24 nor unseen-query/same-corpus 8 establishes reliable general answer quality. Future passage ranking, unit packaging, or budget allocation work needs a new frozen evaluation set; this held-out set must not be silently converted into a favorable tuned benchmark. No product tuning was performed against it.
