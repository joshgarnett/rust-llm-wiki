## Concrete boundary

Freeze these definitions in root-owned `providers/types.rs`, with production constructors/private fields restricted to providers. Do not put HTTP/auth into jobs types.

- `RemoteInput` is a versioned, strict, bounded typed input envelope stored in `TaskSpec.input`: `Embed { inputs: Vec<EmbeddingInput>, expected_dimensions: Option<u32>, representation_fingerprint }` or `Generate { instructions, data, output_schema, max_output_tokens }`. Each embedding item retains its actual text/input hash. Search is reserved for P19; Fetch remains a different public-destination authorization boundary, unavailable in .b. Mutable input DTOs do not carry dispatch authority.
- `ServiceRole::{Embed,Generate,Search}` is distinct from ledger `Capability`. `DispatchPurpose::{Task,Probe { role }}` allows Probe only when the task is explicitly Probe and `.a authorize` grants that underlying role. Probe uses that service's actual body/class/response limits; generation probes remain capped1MiB despite ledger Probe's general8MiB ceiling. No arbitrary URL or inferred endpoint is an input.
- `PreparedWire` is opaque, non-Deserialize, with private bytes/method/exact URL/logical input hash/settings and source bindings/role/purpose/billable proof/settings fingerprints. No public constructor taking encoded bytes, hashes or `TokenBound`. Production construction belongs only to sealed .c encoders; private `cfg(test)` sealed fixture encoders exercise .b before .c without advertising a production wire adapter.
- `WireAdapter` is sealed and provider-private: pure `prepare(loaded_input, trusted_service, task)->PreparedWire`, `observe_usage(status, bounded_headers, bounded_body)->ObservedUsage`, and `decode(prepared,bounded_body)->ValidatedOutput`. It executes no helper/HTTP/repair and cannot schedule callbacks. Observe billing independently of output validation, so valid usage survives invalid output. Whole-body malformed JSON yields unknown usage rather than guessed fragment extraction.
- `Dispatcher` owns VaultFs, CredentialBroker and bounded options; `execute(&self, ledger:&JobLedger, trusted:&TrustedService, task:&Blake3Hash, purpose:DispatchPurpose)->Result<DispatchOutcome,DispatchFailure>` loads the actual retained task input and invokes the sealed adapter. An async internal method drives transport; a bounded synchronous application bridge owns a runtime whose shutdown does not indefinitely await blocking DNS tasks. No public authenticated native transport constructor.
- `DispatchOutcome` returns attempt identity, sensitive `SpoolRef`, allowlisted observation/receipt plan and validated typed output. `DispatchFailure` returns a fixed safe code, `NotSent|Rejected|OutcomeUnknown`, retained attempt/spool/receipt identities when available, and retry decision; never body/header/error-source fragments. Output materializers use existing actual ChangeEngine/Catalog plans before ledger settlement. Dispatcher holds no writer/ledger lock across helper, HTTP or retry wait. The .a broker's bounded per-key refresh serialization is separate and never nested with ledger/vault locks; dispatcher acquires no cache lock itself.

## Transport and retry surface

`Transport` is injected through dispatcher options and gets only an opaque authenticated one-use request plus `TransportLimits` and cancellation/clock context. Public bounded mock constructors may create canned responses/errors but cannot construct send authority, secret leases, a trusted profile or a definite-not-sent proof. Native implementation, authenticated field getters and connection creation remain private. An object-safe boxed Send future avoids another async-trait dependency. Native transport is one request only; it never follows redirects or retries and never decodes content.

`JitterSource::sample_inclusive(max_ms)->Result<u64>` is injected; native uses checked rejection sampling with getrandom. `RetryDecision::{Never,After{delay_ms,reason},Pause{reason}}` and `RetryState { attempts,command_refresh_used }` are non-authoritative data. The dispatcher always re-prepares/revalidates and reserves a new attempt after waiting.

Retry429 and explicitly selected500/502/503/504 with full jitter base1s/cap30s. Parse one bounded valid Retry-After delta-seconds or HTTP date; never wait less than its minimum, and pause if the wait plus a full next timeout cannot fit the remaining deadline. Reject/ignore malformed or duplicate Retry-After deterministically. Command401 can refresh once per logical execution: next attempt is reserved/intented BEFORE refresh, observed credential epoch coalesces process refreshes, new HTTP request consumes a new authorization. Static401/403, successful malformed/schema-invalid output and redirects do not retry. Timeout/reset after possible send pauses unknown unless explicit retry_uncertain, which still requires a new allowance; unresolved exposure never becomes a zero-cost retry. Every wait polls cancel/UTC/monotonic and holds no lock. New process resume cannot reset attempt limit or bypass outstanding unknown accounting; automatic auth-refresh count is execution-local but total retained attempts remain bounded by P15.
