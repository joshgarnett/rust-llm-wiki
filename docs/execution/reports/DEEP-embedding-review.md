## Concrete separate defect: fabricated headings can exceed the bound

`segment.rs:86` parses the first line of `raw[cursor..end]` as a heading even if `cursor` lies **inside an original line** after a capacity split. Header reservation in `render.rs:228–241` scans actual original lines. Thus the two passes disagree: a long unbroken line containing `## <long label>` exactly at a split boundary has no real heading for reservation, but the next segment fabricates a potentially long heading. `render.rs:254–265` adds its JSON header without a final size check. The resulting request may exceed `max_input_bytes`; it is sent whole, not silently truncated. This does not explain a single unit for an oversized source because the whole-note guard still rejects that case.

A second ancestry error uses `Vec::truncate(level - 1)` without retaining heading levels. In a document starting with H2 and then another H2, the first H2 survives as a false ancestor of the next. Both the reservation and splitting passes share this error (`render.rs:238`; `segment.rs:87,97`). Fenced-code heading-like lines are also treated as headings.

Smallest safe fix: share heading recognition/state between reservation and segmentation, only recognize true original line starts, retain `(level,label)` and pop while prior level is greater than or equal to the new level, and defensively reject any final formatted input exceeding the effective byte bound. Fence awareness can be implemented with a small bounded state machine without adding a dependency. Never silently cut synthetic labels to fit.

Regression: construct a single long line where `## ` begins exactly at the body-capacity boundary, followed by a long label; assert no fabricated ancestry and every rendered request is within the bound. Add a skipped-level/repeated-H2 case and fenced-code headings. Existing `tests/semantic_retrieval.rs::short_whole_long_unicode_split_header_limit` covers basic Unicode splitting but not these conditions.
