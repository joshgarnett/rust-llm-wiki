Root moved reset, new ordinary rows, both FTS sets and publication pointer into one immediate transaction, with committed loss/uncertainty latched in `index_meta`. Re-review confirms five precommit injected failures restore old schema/version/vector rows, and after-commit failure/retry preserves notices. Six native migration SIGKILL points now cover the same rollback/committed notice boundary.

**SQL-R2 — resolved: invalid wide evidence span blocks all indexing.** Domain `ByteSpan` accepts u64. A valid envelope with `wiki_span_end=9223372036854775808` against a short snapshot becomes derived `Invalid`, but original span conversion failed the entire generation. Root now emits nullable SQL scalar spans for already-invalid out-of-range values while retaining exact u64 in canonical record JSON/raw text. Re-review of `wide_invalid_evidence_span_remains_diagnosed_and_rebuildable` confirms successful rebuild, verified canonical equivalence, readable invalid evidence and null SQL span.

**Metadata shape follow-up confirmed.** The current reviewed `sql::validate` includes `index_meta(singleton,published_gen,vector_cache_lost,vector_loss_unknown)` at line111. Required loss-notice columns therefore fail preflight when absent. The review question arose while root was integrating its migration patch; it is not an outstanding defect in the reviewed hashes.
