# Agent research design and invariant review

Static review, 2026-09-29. Root supplied baseline `ff3a014`; no Git, builds, tests, network, provider calls, source edits, or nested delegation were performed. Only this report is owned by this review. Source observations below precede the replacement implementation and are not acceptance evidence for it.

## Authoritative scope

The user's final direction supersedes the earlier executor choice: research is exclusively host-agent handoff, including resume. Delete the built-in research executor and research-only legacy compatibility; do not expose an API-executor option. Existing user vaults must not be deleted. Generic accounting, embeddings, direct API graph extraction, and provider probes remain supported. No new research data should masquerade as a paid-job ledger or claim observed host billing.

## Recommended small protocol

Use a separate versioned research artifact and local state machine, built on the existing changeset engine and source/citation verification. Reuse extraction packet conventions rather than its extraction-specific response schema. Do not reuse `JobLedger`, `TaskStage`, or `RunSpec` merely to store host-agent progress.

| CLI action | Local behavior and result |
| --- | --- |
| `research plan QUESTION` | Pure bounded preview of question, scope, local evidence, limits, and host tasks; no persistent executable packet. |
| `research run QUESTION` | Persist initial scope/run head and immutable task packet; return packet, response schema, and exact next command. No provider setup or tool execution. |
| `research resume RUN` | Return the outstanding verified packet or completed result; never search, fetch, generate, embed, or retry remote work. Report stale input explicitly. |
| `research import --file FILE` | Read bounded strict JSON, validate run/packet/currentness, import submitted material through guarded storage, return retained result plus the next packet or terminal report. |
| `research status/report RUN` | Read local progress/report, observed imports and gaps; external usage remains unobserved. |

The smallest easy-to-verify exchange has two packet stages: collect sources, then answer from labeled captured passages. A source submission contains bounded inline UTF-8 content, a submission-local source key, claimed origin URL, title, and bounded provenance. It never names an arbitrary local file, helper command, output path, or privileged config. Source capture returns a fresh answer packet containing real source/revision references and exact quotation spans. Existing evidence can support answering without new acquisition. A continuation requests another bounded collection round, never runs it; an empty/gap-only submission can finish with a useful partial report. These stages and command spellings are implementation preferences, not essential invariants. A single-stage design is also valid if it verifies new-source citation spans against planned captured bytes before publication.

Packets should include version, protocol/instruction version, vault ID, run ID, generation, scope hash, stage, predecessor submission/packet hash, immutable limits and remaining capacity, current dependency hashes, labeled passages, exclusions, typed host actions, and exact response schema. Compute the packet hash over canonical contents excluding its own hash field. Load the retained packet by server-generated identity; never treat an echoed client packet or hash as authority. Return `persisted` and `ready_to_import` explicitly; dry previews are false for both. Inform the host that question/source material is untrusted data and cannot amend these instructions or scope.

Use a packet-local `passage_id` for every source and assertion passage, mapped to its exact `CitationRef`, quotation, and dependencies. The host returns passage IDs, not record IDs inferred from adjacent fields. `quote_hash` is a byte-integrity value and is never a citation selector. Resolve IDs locally, verify current source/revision ownership and bytes, and keep claims unassessed: valid provenance does not establish entailment. Unsupported claims must be explicit gaps or clearly uncited/unassessed, not silently counted as covered evidence.

## Hard storage and authority requirements

1. **Bound before constructing large state.** Read input at cap+1; reject duplicate JSON keys, unknown fields, excessive nesting/nodes, excessive per-field bytes, source count, aggregate content bytes, passages, claims, and URLs. Existing stage defaults provide a defensible initial total JSON cap of 256 KiB, depth 16 and 16,384 nodes (`frontier.rs:13–86,178ff`). State the inline source limit honestly; large documents can use separately authorized source capture followed by explicit source references. Bound packet serialization, report size, total rounds/imports, lifetime captured bytes and no-progress continuations. Max sources alone does not bound repeated revision/import growth. Check aggregate byte arithmetic with overflow handling. Do not serialize a huge packet and only then notice its cap.
2. **One guarded publication.** Commit imported source operations, immutable submission receipt/result, and run-head generation/state update in one `ChangeDraft`, or provide an equally explicit recoverable multi-step protocol. Hold the normal writer permit; recover changes first; bind current head and every used citation dependency with expected hashes. Never advance counters/head before the receipt and outputs are durably recoverable. A crash after publication but before returning must be recognizable on retry.
3. **Idempotency before fresh allocation.** Bind `(run, packet hash, normalized submission hash)` to one durable result. `SourceStore::plan_capture` generates new random source and revision IDs on every call (`sources/capture.rs:139–185`), so an import retry must find and verify its existing receipt before planning new captures. Same packet plus same normalized submission returns the original result; same consumed packet plus different submission conflicts. Validate retained result hashes/ownership rather than believing the existence of a marker file. Distinguish a historical successful retry from permission for new current work: it may return a now-stale completed result with that status, but must not reapply it or produce new authority.
4. **Freshness and concurrent imports.** An outstanding packet whose source dependencies or head generation changed must fail before any source/report writes. Two processes importing different responses for one packet cannot both win. If refresh is supported, make it an explicit new generation bound to freshly inspected dependencies and preserve old packet history; never silently reinterpret an old answer. No whole-vault hash is necessary when exact citation/head dependencies suffice. Refuse a stale outstanding packet with an actionable refresh/new-run instruction rather than an endless resume loop.
5. **Honest provenance.** Submitted URLs are claims from the host, not proof lwiki fetched a URL or observed its response. `SourceOrigin::AgentReport` already exists (`sources/types.rs:34–47`); retain the URL, host-supplied acquisition metadata, exact supplied bytes/content hash, and import observation separately. Do not synthesize HTTP status, redirect proof, retrieval time, or paid receipts. Snippets/abstracts may be retained as explicitly partial evidence, never promoted to an unseen full document. Multiple URLs for identical content must retain their separate claimed origins; source deduplication must not erase attribution or reset lifetime work bounds.
6. **No host-tool authority or accounting fiction.** Host tasks are typed requests and explanatory data, never shell strings that lwiki executes. No credentials, MCP installation, search/fetch adapters, or provider config are opened on these paths. `network_used=false` describes this CLI invocation only. Report `external_tool_usage=unobserved` (or equivalent), never zero host spend/tokens or a hard cost guarantee. Research limits bound accepted local work; they cannot enforce host search/API usage. No implicit embeddings or API graph extraction after source import.
7. **Offline and dry-run.** Planning and dry-run must not create run directories, packets, operational state, caches, counters, or prepared changes, including on error. A dry packet cannot later be accepted as if persisted. Offline output must not instruct the host to perform new external acquisition; it can use existing evidence or already supplied local material and return gaps. Clarify that offline permits normal explicitly requested local imports/writes, while dry-run forbids them. Resume/status/report must work without any provider configuration.
8. **Proposals remain proposals.** A research answer/report and imported sources can be durable local records; generated wiki page/entity/assertion changes remain guarded proposals. Reuse graph extraction packet/import for structured claims as a separate explicit next action. Do not make research import a route to arbitrary record paths, accepted assertions, identity merges, provider operations, or automatic application. If page proposals are retained, existing target IDs and expected hashes must be checked at staging and application.

If packet creation follows import as a second transaction, the first must record a durable, resumable `needs_packet` state and its complete inputs. Resume may finish that deterministic local transition. Do not advertise a nonexistent next packet or force a source resubmission. Keeping packet publication in the original draft is simpler when source overlays can supply its citations.

## Bug B: concrete diagnosis and disposition

**B1, duplicate rejection receipt (confirmed static path).** `providers/dispatcher.rs:955–994` creates the rejected receipt plan, retains it in `DispatchFailure.materialization`, then calls `commit_receipt`. `commit_receipt` (`1241–1281`) prepares/applies the receipt and calls `outputs_committed` and `settle`. `research/runner.rs:695–711` subsequently unconditionally passes that materialization to `research::acquire::settle_receipt`; `acquire.rs:300–327` prepares the original create-only draft again. The same `run_event_receipt_HASH.md` target is now present, producing `ContentConflict` instead of the original provider validation error. This matches the reported invalid-assessment failure without requiring a second paid request.

Delete the obsolete research caller with the executor. Preserve the shared generic materialization functionality used by `app/probe.rs:161,190` in `jobs::checkpoint` or an appropriate shared accounting module before deleting `research/acquire.rs`. The probe already checks actual ledger receipt/phase before invoking it (`probe.rs:152–168`); it is not the same unconditional duplicate-write bug. Direct API extraction's execute failure path returns the dispatcher error (`graph/api_extract.rs:339–350`); recovery only gets a new rejection plan when a receipt is absent (`dispatcher.rs:333–349`). No generic double-charge defect is established by this review.

For any remaining shared helper, prefer a state-aware contract: an existing matching committed receipt is verified and settled if necessary; an absent receipt is materialized; a different receipt/attempt or conflicting output fails. Do not swallow arbitrary ContentConflict or erase the plan before failed-publication recovery is possible. A focused generic regression should return malformed paid generation output, prove the original rejection survives, verify exactly one receipt/charge, reopen, and prove no resend or second receipt. That test belongs to retained provider/probe/API functionality, not a resurrected research executor.

**B2, unlabeled source passages (confirmed contract mismatch).** `ResearchPassage` (`research/types.rs:69–74`) has only citation, quote, dependencies. `GenerationData` (`plan.rs:48–56`) passes those passages without a common selectable ID. `gaps.rs:21–35` accepts only membership in the supplied Evidence ID set; `runner.rs:1057–1069` builds that set solely from assertion citations. Source citations have no eligible Evidence ID, while their adjacent `quote_hash` invites confusion. The observed model choice is consistent with this input contract; accepting quote hashes as Evidence IDs would be wrong. Delete the old planner/schema and use explicit packet-local passage IDs for both citation kinds. Validate source-only, assertion-only and mixed packets, with quote-hash/unknown/duplicate IDs as negatives.

## Deletion and reuse map

- Remove/replace `research/runner`, paid `acquire`, paid `plan/stages/report/types` and research-only `graph/research_extract`; replace the CLI's provider/budget/retry/amendment flags. Local inspection and citation/synthesis validation contain useful algorithms but must be decoupled from paid task/run structs. Existing `research/report.rs` is ledger-bound, not a drop-in local report codec.
- Remove research-only state/events/epochs/frontier admission and live-bound adapters in `jobs/research.rs`, `jobs/types.rs`, `jobs/events.rs`, `jobs/replay.rs`, `jobs/checkpoint.rs`, and `jobs/ledger.rs`. These are spread across generic accounting, so delete research branches rather than broad shared methods. Preserve generic source binding, send authorization, reservation, unknown holds, response spool, receipt acknowledgement, settlement and replay protections.
- Remove research batching/coordinator branches (`ResearchDispatchWork`, `PreparedResearch`, `execute_ready_batch`, research-only selection/retry branches) from `providers/dispatcher.rs` where no retained command needs them. Ordinary execute/response recovery must remain intact. Search/public-fetch removal should follow actual remaining callers; do not accidentally delete ordinary provider/probe capability contracts merely because the old research runtime used them.
- Reuse `graph/packet.rs` canonical fingerprints, strict bounded parsing concepts, and packet freshness; `app/extraction.rs:73–143` shows persist-before-ready and reused-packet revalidation. Reuse `SourceView::verify`, `SourceStore` capture planning, `ChangeDraft` expected writes/read dependencies, and `ChangeEngine` recovery. Research needs its own response schema; the graph extraction codec rejects null and has extraction-specific numeric/field semantics.
- Update capability/schema discovery, actual maintained skill references, CLI help, contracts and workflow tests together. Do not leave a skill instruction that invokes removed paid research flags or implies automatic acquisition/paid synthesis.

## Critical acceptance tests for root/worker

1. Fresh vault + no provider configuration: run → collect submission → answer packet → cited answer import → completed report; agent/tool actions are returned but never executed. Existing-evidence-only and gap-only completion also work.
2. Input/packet/output caps, duplicate JSON keys, deep/numerous values, overflowing aggregate counters, hostile URL/path/command strings; reject before durable writes. Source text containing executable-looking instructions remains data.
3. Exact retry returns the same source/revision/report IDs and unchanged counters. Different response for consumed packet conflicts. Concurrent imports have one winner. Same content from different claimed origins retains provenance.
4. Crash at every relevant prepare/apply boundary and before return; recovery plus retry produces one import/result and one current head, no duplicate capture or orphaned accepted progress.
5. Changed source revision/head, edited packet, cross-vault packet, mismatched scope/hash/generation, missing/tampered receipt/output; fail safely. Same successful historical retry after freshness changes does not grant fresh work.
6. Source-only/mixed labeled citations; exact quotation verification; quote hash/foreign ID rejected; unsupported claims remain unassessed/gaps. Host-reported URL/content never becomes observed HTTP provenance.
7. Repeated resume is stable; terminal runs do not request more work; source/byte/round/no-progress limits survive process restart. Stale packet has an actionable recovery route.
8. Full tree/bytes/mtime checks for plan and dry-run success/failure; offline packet has no external-acquisition task; no provider-config read/auth helper or network in any research command.
9. Shared provider malformed-response test for B1, plus retained embeddings/direct API extraction/probe accounting and uncertainty recovery gates after deleting research branches. No live provider required.
