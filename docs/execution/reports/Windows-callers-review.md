# Windows caller integration source audit

Sol independent caller audit, 2026-09-28. Scope: current Windows integration in `src/vault/{fs,lock,operational,mod}.rs`, provider protected-read routing, the held-handle helper API and changed Unix creation defaults. Only this report was edited. No Cargo, source edits, delegation, Windows execution, or native qualification occurred. Root received findings promptly and revised several callers during the audit; statuses below distinguish those source corrections from executed acceptance.

## Findings and source corrections

1. **High — incompatible stage-verification reopen. Source correction inspected.** Initial `RunLedgerGuard::replace_path` held a writable stage and called `read(&stage,limit)`. Windows `read_protected` uses only FILE_SHARE_READ, so that new open denies the existing stage writer's required sharing and fails with a sharing violation. Root now uses `cfg(windows)` to rewind and read the same held read/write stage, at most limit+1 bytes, with `same_inode` before and after; the original stage remains held through rename and the separately pinned Private parent remains held through cleanup. Unix keeps its pathname-read branch because Unix NativeIo private stages are write-only. Recommend also checking final held `metadata().len() == retained.len()` to match the helper's final-size contract. The corrected path still requires actual Windows behavior qualification.

2. **Medium — reopened operational directories were not checked as Private. Partial source corrections inspected; enumeration closure pending.** Initial `RunStore::new/open_existing` retained only the IntegrityProtected root. Generic protected reads check ancestors for integrity, which deliberately permits outside reading/listing. Thus a preexisting jobs/run/requests directory with outside read grants could be accepted even though the operational directory contract is Private. Root now attempts to pin every existing managed directory: root/.wiki/state use IntegrityProtected, jobs/run/requests use Private; genuinely absent directories are left for bootstrap. `read_windows` additionally holds the immediate Private parent for private file reads. These changes restore private validation on file reads and existing stores. Remaining standalone `discover_existing` must itself retain a Private jobs-directory guard before `read_dir` and validate each run child with a Private directory guard, including all reparse attributes. `enumerate_spool_ids` should independently retain a Private requests guard and per-attempt guard across ownerless-directory enumeration, because a RunStore constructed before a directory exists has no persistent guard for that later directory. Per-attempt cleanup guards must be released before removing that directory while its protected parent remains held; keeping a no-delete-share attempt guard through `remove_directory` would defeat cleanup.

3. **Medium — Unix private adapter defaults did not enforce creation-time privacy. Source correction inspected.** Initial DurableIo private methods delegated ordinary creation on Unix. A custom adapter inheriting that default could produce 0644/0755 objects and rely on later chmod. NativeIo itself correctly creates 0600 files/0700 directories. Root now defaults both private operations to Unsupported on every platform; adapters must explicitly implement the stronger contract. Operational and accounting fault wrappers explicitly forward NativeIo private creation inside their existing observed fault boundary. This preserves the ability to inject creation failures without silently substituting ordinary creation. No tests were run by this audit.

4. **Compile/lint — unused policy module under macOS unit-test cfg. Source correction inspected.** Initial `cfg(any(windows,test)) mod acl_policy` exposed a private policy module to macOS library unit tests without consumers, producing dead-code warnings under strict gates. Root changed it to `cfg(windows)`; portable integration tests import actual source by path. The helper's optional `CheckedFile::identity` accessor currently has no caller and can be removed or deliberately consumed before full Windows strict lint. `file/file_mut` now have P14 consumers according to root; those consumers are outside this storage caller review. No Windows API signature mismatch was found statically in the reviewed calls.

## Positive source observations

- Provider config and credential files select Private. Both initial/rechecked custom CA material select IntegrityProtected. Windows returns bytes only through bounded `read_protected`; the existing Unix inode/mode checks remain in the non-Windows branch. Operational WIKI.md reads separately select IntegrityProtected rather than the private job reader.
- WriterPermit uses the creation-time private lock helper, retains its entire pinned ancestor chain, and checks every guard plus the actual held FileIdInfo identity/security in `require_root`. RunLedgerGuard similarly retains the no-delete-share lock chain and repeats held-file/path and store binding checks before operations. Root replacement of a canonical pathname by itself cannot be mistaken for the original identity while those handles remain held.
- NativeIo private files/directories route through explicit SECURITY_ATTRIBUTES creation on Windows and mode-at-create on Unix. Existing Windows private objects are validated, not ACL-repaired. Operational bootstrap pins created directories before authority-file creation. Private stage creation through DurableIo remains visible to fault adapters; replacement retains an independently pinned Private parent after NativeIo releases the helper's temporary creation guards.
- NativeIo directory sync invokes checked Windows inspection and returns Unsupported. RunStore converts Unsupported into CapabilityUnavailable, preventing successful durable private-job barriers. WriterPermit still ignores the DirectorySync enum while bootstrapping lock directories; this supplies OS lock authority only and cannot be cited as evidence of supported Windows directory durability. Existing changeset journal code separately refuses unsupported directory durability. No broader storage-durability review was performed.

## Final source closure, 2026-09-28

Root requested one bounded source rereview after the remaining corrections. All findings above are **closed in the reviewed source**, with no additional scoped caller defect found. This closure is source-only; no Cargo or native test was run by this rereview.

- `discover_existing` retains a Private jobs guard through enumeration and final vault recheck, and validates every discovered child under a per-iteration Private guard before retaining its ID. The helper rejects all reparse attributes on both parent and child.
- `enumerate_spool_ids` independently retains a Private requests guard for the whole enumeration and a Private attempt guard for each owner read and ownerless-directory check. `read_spool` likewise retains its Private attempt directory through ownerless checks and response reads.
- `remove_empty_attempt_dir` holds a Private attempt guard through owner/data/entry checks, owner removal and child sync, then explicitly drops that guard before `remove_directory`. A **separate** Private parent guard remains held through removal and parent sync. The separate parent is necessary because RunStore can initially skip a nonexistent requests directory; this final implementation no longer depends on requests having existed when the store was constructed.
- The held Windows stage read now checks `metadata().len() == retained.len()` after bounded reading and repeated held security/identity proof. It verifies the hash through the same open read/write stage and retains that stage through rename. No incompatible ReadOnly reopen remains in the Windows stage branch.
- The unused `CheckedFile::identity` accessor was removed. Portable policy remains Windows-only in library cfg; its portable integration tests continue to import actual policy source directly. Private adapter defaults remain Unsupported on all platforms, with explicit NativeIo forwarding in the reviewed operational/accounting fault wrappers.
