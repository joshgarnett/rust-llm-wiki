## Proposed smallest shared surface

Root freezes `src/jobs/types.rs` before implementation:

- `JobLedger`: bound VaultFs, vault ID and run ID, injected durable I/O/clock/faults; no shared open journal or held lock. `RunSpec`: schema/version, input/scope/config/source fingerprints, immutable initial limits/deadline and ordered task specs. Canonical `RunState`: Planned, Running, Paused, Completed, Failed, Stopped.
- `TaskSpec`: actual complete input/prompt/schema/model/settings fingerprint, stable key/priority/dependencies and capability. Task states are Pending, Running, Completed, Failed; task completion requires validated committed output, rather than known billing. M4 stages/frontier planning are deferred.
- `AttemptRef`: run/task/unique opaque attempt ID/attempt number and bound request hash. Work phases Reserved, DispatchIntent, Received, OutputCommitted, Settled; billing is separately Reserved, ReleasedNotSent, KnownSettled, UnknownReserved. Valid output can be reused while an unknown charge remains outstanding. A retry always allocates another attempt/reservation.
- `ExecutionPolicy {offline,dry_run,retry_uncertain}` plus in-memory cancellation token. `AttemptBound`: capability and complete wire/input hashes, nonsecret endpoint/model/config fingerprints, exact request bytes, response ceiling, token-class bounds, optional conservative cost/rate-card quote and expiration. These are pure P16 adapter/preflight outputs, not secrets, URLs or transport handles.
- Checked `Money {currency,nanounits:u64}`, validated currency, rational `Rate {price_nanos,units}`, immutable `RateCard` identity/hash/version/validity/currency/per-request fee/all billable-class rates. `TokenBound`: Exact, ProvenUpper, Estimate, Unknown, with method/tokenizer identity. Intermediate multiplication/sums use checked u128 and upward division; final amounts must fit u64. No floats, implicit currency conversion, missing-field zero or inferred cache discount.
- `UsageReceipt`: attempt/task/capability/profile/endpoint/input/model identities, safe provider request ID, KnownOrUnknown usage/cost, billing disposition, retained reservation/rate identity, durable record refs/hash bindings, cache-only space/input/vector hashes and safe failure code. `OutputDisposition`: Validated, Rejected, Unknown. Immutable bounded receipt/event notes survive vector-cache deletion.
- `LedgerEvent`: version, sequence, event ID, run/attempt IDs, expected previous checksum, timestamps and typed transition/amendment payload. `ReplayReport`: classified attempts, exact committed outputs/receipts, unknown allowances, orphan/conflicting spools, missing vector coverage and accounting-completeness status. Unknown charges are never folded into known spend.
- `Reservation` and `DispatchPermit` have private fields, no Deserialize or Clone. P16's private transport consumes a newly returned permit once. Replay never reconstructs permission to send an old dispatch intent.

Proposed methods: pure `plan_attempt/check_bound`; `create/inspect/add_tasks/start`; `reserve(task,bound)`; `dispatch_intent(reservation)`; `release_not_sent(proof)`; `spool_response(permit,bounded_response,safe_metadata)`; `materialization_plan(attempt)`; `record_outputs_committed(attempt,exact_bindings)`; `settle/reconcile`; `pause/stop/resume(recorded_amendment)`; `replay`. Every result/error preserves run/attempt/receipt identifiers. Proof of NotSent belongs to the trusted dispatcher boundary, not a user-controlled Markdown status.

## Admission and ordering invariants

Under one short cross-process run-ledger lock, replay authoritative frames, verify current run/input/config bindings, check state/cancellation/deadline and `settled + outstanding + proposed <= limit` component by component, then append/fsync admission. Defaults: lifetime requests60, concurrency2, attempts3/task, deadline15 minutes; byte/token ceilings come from bounded operations/profiles. Counters never reset on resume. Only explicit recorded user amendments raise limits or extend deadlines. Stable task priority/key determines readiness; a dependency failure cannot silently dispatch dependent work.

Request slots remain consumed after intent. Definite never-dispatched work alone releases them. Unknown outcome retains money and unresolved unit exposure; new uncertain retries require their own bounds. Hard cost requires complete applicable rates and proven bounds for every billed class, including invisible output/reasoning and request fees. Estimates are display only. Incomplete/expired/mismatched rates reject a requested hard-cost guarantee while request/byte controls may remain usable. Rate applicability must cover the attempt's possible billing interval, or explicitly establish dispatch-time price locking. Provider usage above a bound records overspend, invalidates the guarantee and stops new admission; it is not clamped away.

Release the ledger lock before helper/HTTP or acquiring a vault writer. Authentication follows reservation; fsynced dispatch intent immediately precedes possible send. P15 contains no authenticated transport constructor or request executor. Cancellation prevents new intent/admission, preserves completed work and marks unresolved dispatches; it cannot retract accepted remote work. Persist UTC deadline plus last observed UTC high-water mark; monotonic elapsed governs live waits/timeouts. Clock regression pauses conservatively rather than creating extra time. Resume revalidates all input/source/config/output bindings and outstanding attempts before scheduling.

## Persistence and replay

Use a fixed advisory lock inode and length-framed checksummed append-only operational journal under `.wiki/state/jobs/<run>/`; PID text is diagnostic. Canonical run/events live under `runs/<run>/`. Create bootstrap paths under the vault writer before acquiring the ledger lock. Subsequent private operational writes need a narrow root-bound run permit/I/O helper, not bypassed canonical mutation authority. Reuse DurableIo injection for crash/fault tests; do not hold the run lock while acquiring WriterPermit.

Fsync bounded successful response bytes and allowlisted metadata into restricted `.wiki/state/requests/<attempt>/` before Received. Exclude auth/helper output and diagnostic provider bodies. Unique attempt spool files use expected absence/hash identity, bounded reads, regular-file containment and restrictive permissions. Failed spool durability leaves outcome unknown. Validate/materialize outside ledger lock; canonical receipt/output/run-event changes use real ChangeEngine/GraphValidator/Catalog guarded writes. A durable receipt is required even for malformed paid responses. Verify all actual output/receipt hashes before OutputCommitted/checkpoint/settlement; delete spool only after verified committed outputs. Failed cleanup is replayable, not duplicate billing.

Replay identifies transitions by attempt/event IDs, verifies hashes across operational journal, spool, Markdown receipts/output and cache-only refs, and settles each attempt once. A torn trailing frame may be ignored; checksum/sequence corruption or unfamiliar run edits conflict. Dispatch intent without durable response is UnknownReserved even if no request actually left. Complete spool without Received can be reconciled by its bound attempt/hash, without another request. SQL commit/cache loss never manufactures missing vector bytes or paid regeneration. Markdown-only restore can recover recorded work but lacks authority to resume the old hard-cost budget; a new run must disclose prior unknown spend. Coordinated rollback of every local durable store cannot be detected without an external monotonic authority; do not claim it can.

## Root choices before freeze

1. Conservative concurrency proposal: retain possible-remote-inflight exposure after OutcomeUnknown until completion/reconciliation or an explicit recorded limit amendment. A received terminal response releases concurrency even if money/usage remains unknown. If concurrency instead means only local active transport, name/report that narrower guarantee explicitly.
2. Explicit resume may restart Paused/Stopped runs with unchanged lifetime limits after reconciliation; Completed work is reusable but cannot reset counters. Confirm canonical transition policy and amendment command ownership.
3. Freeze payload/frame/task/journal replay bounds, provider receipt allowlist and sensitive-spool permission adapter. Suggested spool ceilings match existing contracts (generation1MiB, embedding/fetch8MiB); metadata64KiB and event256KiB require root approval, not invented unbounded schemas.
4. Define authoritative complete-history marker/checkpoint binding and how run-note/journal disagreement is classified. Missing operational accounting always blocks old hard-cost continuation; local rollback-detection limits must remain explicit.

## Concrete interface proposal after root choices

The file defines validated Currency/Money/Rate plus RateCard/TokenBound and applicable billed classes; RunSpec/RunScope/TaskSpec; AttemptRef/AttemptBound; separate AttemptPhase/BillingDisposition/RemoteExposure; UsageReceipt/ResponseMetadata/SpoolRef; LedgerEvent/JournalFrame/EventPayload; canonical and vector-cache output bindings; replay/budget/task inspection DTOs; injected clock/fault/cancellation/options; and private authority/ledger state. Times use checked UTC-millisecond DTO inputs, rendered RFC3339 for canonical fields; live monotonic readings are never persisted as cross-process authority. Own keys/fingerprints/checksums are excluded from their own canonical hash input. Missing usage/classes/rates never mean zero.

Public `JobLedgerApi` covers construction, pure bootstrap plan, held-writer create, inspect/replay, task additions/readiness/local completion, start/pause/stop/explicit resume, pure bound check, reserve, dispatch intent, materialization plan, verified output commit and checkpoint plan. Root may expose identical inherent methods instead of the proposal traits. `JobLedger` owns VaultFs/IDs/options and no held lock/connection. Canonical plans go through the actual ChangeEngine/GraphValidator/Catalog; output acknowledgment verifies the prepared change and exact committed hashes rather than trusting a caller flag.

Crate-private `DispatcherLedgerApi` covers consuming intent authorization, definite-not-sent release, outcome unknown, bounded response spool recording, settle/reconcile and cleanup. The concrete sequence is `reserve -> credentials -> dispatch_intent(Reservation) -> begin_send(DispatchPermit) -> private transport consumes SendAuthorization`. Authorities have jobs-private fields, no Clone/Deserialize/public constructor; begin_send rechecks state/cancel/deadline under the short run lock and records one authorization. The dispatcher saves an ordinary AttemptRef before consuming send authority. Post-send `record_response(&AttemptRef, ResponseSpoolInput)` validates the stored genesis/request/bounds binding and permits response recording after cancellation/deadline; replay supplies only identities/classifications, never send authority. NotSentObservation is crate-private trusted dispatcher input; deserialized event reasons cannot release budget.

`concurrency_admitted` includes Reserved and possibly-inflight attempts; `remote_inflight` reports the conservative possible remote subset. Terminal response/reconciliation can release concurrency while unknown money remains reserved. `PersistenceAllowance` additionally reserves mandatory remaining journal bytes/event slots at admission, preventing complete-history ceilings from stranding a dispatched receipt. Actual overspend is recorded without clamping and stops further admission. Event checksums frame the encoded event core, avoiding a self-checksum cycle. Missing-history inspection has optional last-event/run-note bindings and cannot yield admission authority. Inspection exposes effective amended limits/deadline separately from the immutable genesis spec. Creation must derive/validate prior-accounting disclosure against local retained runs; caller-supplied `None` cannot hide known missing history.
