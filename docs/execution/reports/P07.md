# P07 — literal and lexical retrieval

Base: accepted P05 `6158b5810908dffbea8251ddd386831143bc24ba`. Worker owns only the five retrieval leaves, `tests/retrieval_lexical.rs`, and this report; root owns public types, exports, application/CLI integration, Cargo, state, and commits.

Implemented `search(&ReaderSnapshot, &str, &QueryPlan)` and pure `lexical::validate_plan`. Search never opens/synchronizes a catalog or calls a provider. Literal mode matches exact case-sensitive UTF-8 substrings in original allowed document bytes, including managed envelopes, evidence quotations, and extraction audit text. Those artifact excerpts remain `NoteText`, without source citations. Default lexical FTS omits those bodies, safely quotes each whitespace term and binds an OR expression, with no advanced operator syntax.

Exact IDs rank first, then exact titles/aliases, then SQLite BM25 with stable ID/path ties. Labels never merge identities. Every leg applies kind/tag/source/path/authored-status and eligibility policies before its cap; tags require all selected values, other lists accept any selected value, and dimensions combine with AND. Current entity identity seeds search title/alias only when its description is ineligible. Historical/withdrawn text requires explicit history inclusion; proposed assertions require explicit inclusion. Invalid and unadopted notes remain honest path/hash discovery.

Limits are query 4096 bytes, lexical 64 whitespace terms, displayed hits 1–50 (default 10), candidates 1–80 (default 80), excerpts 1–2048 bytes (default 240), at most 64 highlighted matches, and at most 80 unique normalized items per filter list. Duplicate-heavy lists normalize before that ceiling. Blank/NUL queries fail with `Usage`; punctuation-only lexical requests receive a literal-mode hint. Cursors bind complete generation/parser/control snapshot plus query/mode/normalized filters/limits. Multi-leg lexical omission counts are conservative lower bounds; literal counts all filtered matching documents.

Excerpts are exact original UTF-8 slices. A private connection-borrowing RAII adapter uses the actual bundled `unicode61 remove_diacritics 2` FTS5 tokenizer, with pointer/version/return-code/boundary checks, callback unwind containment, and instance/statement cleanup. Parser/token maps report exact match spans only when original bytes equal mapped text; transformed events retain raw excerpts without fabricated match offsets. Only intact eligible captured payloads in `VerifiedSnapshot` receive source span/hash citations. Explicit `IndexSnapshot` returns no citations and preserves owner/source locators.

Checks: `cargo check --locked --offline --all-targets` passed in 1.66s; after root's added application fields, target compilation also passed. `cargo test --locked --offline --test retrieval_lexical`: **13 passed**, 0 failed, 2.02s (0.36s compile). All five named P07 gates pass, plus exact-ID/homonym ranking, identity/description split, native Unicode/CRLF captured spans, artifact exclusions/literal audit, query/candidate limits, pure validation, conservative Markdown mapping, and real source withdrawal through `ChangeEngine` + `CatalogGraphValidator`. Initial failures were integration compiler races and two fixture mistakes, corrected before passing.
