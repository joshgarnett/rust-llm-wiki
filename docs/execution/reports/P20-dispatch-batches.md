## Implemented behavior

- Public leaf DTOs: `ResearchDispatchWork { task_key, service, purpose }`, `ResearchDispatchOutcome::{Remote,Public}`, per-task `ResearchDispatchResult { task_key, outcome }`, and `ResearchDispatchBatch { outcomes, stop }`. `Dispatcher::execute_ready_batch(ledger, work, public_options)` prepares the whole selected work slice, sorts by task priority/key, rejects duplicate/unknown tasks, calls ledger `reserve_ready_batch` once, and only then constructs/polls bounded one-attempt futures. Each opaque reservation has its ordered result even if a sibling fails or a later reservation stopped. A caller-selected subset must be the ledger's initial eligible prefix; it cannot dispatch a lower-priority task to win the final slot. No public SendAuthorization escape.
- Current research services use typed `(profile_id, capability)` effective binding entries plus effective config/profile/endpoint proofs. Generate and Search may share a profile name. Only research stamps `AttemptBound.profile_fingerprint=Some`, recomputes the allowance fingerprint, and calls `history::retain` before reservation. Legacy proof/codec remain absent, preserving omitted-field serialization and existing retry behavior.
- Research `execute` and `execute_public` use the same stable batch admission with a one-item prefix. Remote research dispatch sends once. Retry-After/backoff decisions are returned and journaled through `schedule_research_retry_after`, which computes actual `not_before` under the ledger lock. No research worker sleeps/retries privately. Legacy retries/401 refresh remain available unchanged. Proven NotSent behavior remains unchanged rather than broadening the retry policy.
- Public Fetch is privately split into preparation and consumption of an opaque reservation. Preparation checks canonical descriptor/source/fixed adapter bindings and uses the effective research config. Sending rechecks sources and performs DNS/HTTP outside ledger locks. Known unentered failures release reservations; entered uncertain failures retain holds/spools. Dispatcher network activity is set only after public transport entry, including entered failures; retained reads/pure connector preparation never set it.
- Retained credentialed decoding uses `history::restore` when the recorded codec exists; legacy decoding restores the originally recorded optional profile proof before exact bound comparison. Current-model/config mismatch stays a recovery failure with protected spool; it is never classified as provider rejection. Original codec implementation belongs to Astra's separate lease.
- Final source inspection identified receipt-planning errors after paid response retention that inherited `NotSent` from the generic failure constructor. Those two paths now preserve the paid spool and report `OutcomeUnknown` for local successful-output planning failure or `Rejected` for an already rejected response. This tiny final correction was formatted/static-checked after the last targeted run and awaits root's compilation/integration gate.

## Root integration notes

- Dispatcher DTOs are already accessible through the public `providers::dispatcher` module; no re-export is required unless root wants one.
- Required shared additions now exist: optional omitted `AttemptBound.codec`, private `Reservation::bound`, exported private history module, and `JobLedger::schedule_research_retry_after`.
- Runner selects only current eligible work (including elapsed scheduled retries), observes `batch.stop`, and materializes every outcome; local work is executed separately before requesting a remote prefix. Prior protected response without acknowledged receipt blocks new sends.
- Caller-supplied stale/non-prefix work returns an outer admission error without sending; a successfully reserved prefix returns per-task outcomes and stop cause. Unknown holds continue to consume lifetime accounting.
