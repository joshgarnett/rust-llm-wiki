# End-to-end audit of lwiki 0.1.2

Date: 2026-09-29. Audited checkout: `63b2439f5cd57211e2a2bc5587ac5bace3d03ea2`. Released product: `d8a82a5a345549fada06987dec986801c6842252`, tag `v0.1.2`. Source, schemas, maintained skill, Cargo manifest and lockfile are unchanged between the tag and audited checkout. Behavioral reproductions used the downloaded macOS ARM64 release executable.

**The audit found open correctness and workflow gaps. Historical M0–M4 acceptance does not close these new findings.** The highest priorities are a conflict state with no supported resolution, a source-identity inconsistency that can cause API extraction to dispatch and then panic, and failed embedding probes that block subsequent embedding work. This is an audit and work list: no product fixes, release changes or new built-in research executor are included.

## Method and coverage

The user requested an end-to-end comparison with reference examples and documentation, split across subagents. Two Sol reviewers covered graph/retrieval and CLI/agent workflows. Astra independently reviewed storage/canonical authority, then provider/accounting recovery. Root checked reference-to-product alignment, build/release/test coverage, reproduced embedding diagnostic loss, inspected worker evidence/source paths, and invoked the full local regression suite. A cross-module follow-up traced the storage duplicate-ID finding through actual API extraction rather than stopping at packet export. Astra also reviewed the consolidated claims and recommended fixes.

The original [LLM Wiki reference](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f) emphasizes accumulating maintained synthesis, not merely retaining reports. The comparison also revisited claude-obsidian's separated evidence/draft/canonical-write workflow, QMD's bounded retrieval, Basic Memory's shared Markdown, LightRAG's graph-plus-source retrieval, and zk's CLI navigation. Their features are design comparisons, not automatic requirements or dependencies; sources and boundaries are linked in the reference report.

During the audit the owner supplied a [live 0.1.2 test report](AUDIT-owner-test-0.1.2.md): all B1–B13 dispositions, 30 offline smokes, 36 recipe steps, four live gateway probes and the refreshed Cedar API lifecycle passed. Real Wixom extraction exposed N1–N5 and still-current decision text after withdrawal. The reviewers followed these through local code and disposable reproductions before closing their reports. Live model outcomes remain owner-reported; local findings do not establish the cause of the gateway's Haiku HTTP 400.

## Prioritized work list

Priorities reflect impact and evidence. “High” means a demonstrated operational blocker or crash worth fixing before promotion of another release. “Medium” includes incorrect/misleading behavior and important incomplete workflows. Product proposals are labeled separately from contract defects.

[S1](AUDIT-storage.md) | Add explicit guarded conflict resolution, retain unfamiliar author bytes, and test the transition to a terminal state through crash/restart boundaries. |
| 02 | **High — canonical authority / crash** | A syntactically broken note with a duplicate source ID is rejected by the catalog but ignored by source/packet reuse. A local API reproduction sent one generation request, then panicked at `src/catalog/eligibility.rs:865` with exit 101 and no JSON envelope. Separately, after a valid API output was retained, introducing that duplicate made ordinary `check`, index sync, search and graph query panic. [S2](AUDIT-storage.md), [cross-module follow-up](AUDIT-graph-retrieval.md) | Use one canonical identity-reservation rule; reject ambiguous sources before dispatch/reuse authority; make generation-output eligibility handle absent/invalid sources without panic; preserve/recover the retained paid attempt. |

Every implementation finding above has exact source locations and reproduction details in its domain report. The duplicate-source/API panic leaves the received response spool and reconciled accounting journal intact; it does not demonstrate a lost or refunded charge. No accepted invalid assertion, credential leak, overspend, or duplicate automatic request was established by these reproductions.

## Recommended sequence

1. **Finish recovery and authority boundaries:** 01–05, then API preflight/diagnostics/retry work 17–20. The owner could extract only one of six real-world source variants, so the exact rejection/repair path deserves priority even though strict quotation validation is intentional. Coordinate source authority and paid-output publication so invalid inputs cannot cause paid work followed by a panic, and preserve unknown charges on every retry.
2. **Make retrieval/output honor caller intent:** 06–11, 15 and 23. Add regressions that combine filters, multiple evidence sources, segmented corpora, navigation, and source changes after report completion.
3. **Complete the host-agent product workflow:** 12 and 21–22. Use a realistic research task to create and maintain linked topic/entity pages, not just generate a report. Demonstrate repeat ingest, contradictions, source retirement, author edits, and cache rebuild. Treat a multi-page CLI interface as a scoped design addition; do not introduce a built-in research executor. Relevance-selected research passages are another quality opportunity: the disclosed 4 KiB source-prefix policy works as documented but misses late sections; keep the full source, precise spans and explicit omission budgets when improving selection.
4. **Align docs and release gates:** 13–14 and 16. Make each new behavioral regression part of the appropriate default gate and refresh the test-agent guide for the next build.

## Verification and limits

The full uncached local Rust/Bazel invocation passed **47/47 targets: 577 passing parent cases, zero failures, seven ignored helper entries**, in 1,776.311 seconds. Root also ran all **41 Python tooling tests** successfully. These are the existing tests; the audit's new reproductions expose missing cases rather than failures of the current suite. All 329 frozen product/schema/skill/test/build files matched their pre-audit hashes afterward. Final commands, per-target counts, source identity and reproduction evidence are recorded in [AUDIT-checks.json](AUDIT-checks.json).

Reproductions used disposable vaults and synthetic loopback providers, including three diagnostic comparisons, a two-document semantic corpus, invalid/uncertain provider responses, and offline storage/agent flows. They do not qualify a live gateway, real model quality, actual billing, installed host discovery, or other native platforms. Existing six-platform build/artifact evidence is in [RELEASE-0.1.2.md](RELEASE-0.1.2.md); it was inspected, not rerun or changed by this audit.

Open qualification remains explicit: native Windows writes, full recovery on other intended hosts, clean-machine/installed-copy behavior, actual skill discovery and Obsidian GUI use, broader held-out real-model retrieval/extraction quality, and owner distribution decisions. The fixed corpus has eight questions with synthetic vectors; the owner's live Wixom tests are useful additional observations, not a broad benchmark. HTML extraction, local models, MCP, ANN/reranking/community summaries and an ownership predicate are separate scope/quality decisions; the removed built-in research runner is not missing work.
