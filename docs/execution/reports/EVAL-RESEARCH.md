# Context evaluation research and implementation

## Source-count diagnostic and discovered validation ceiling

The [reproducible diagnostic](../../testing-large-vaults.md#development-diagnostic-for-validation-memory) passed its 12-command smoke protocol, including seven intentional rejection cases. At 1,000 sources containing 100,000,000 UTF-8 content bytes, all five diagnostic commands passed. Public graph validation checked 3,008 controls and 5,008 unique dependency guards in 21.683 seconds, with 113,311,744 bytes native peak RSS. The separate full projection retained 201,261,637 bytes of retrieval text and reached 333,217,792 bytes peak RSS. Validation performs proposed and baseline projections; full projection performs one, so their timings are not a direct speedup comparison.

The frozen safety calculation admitted the 10,000-source tier. Generation and exact fixture audit passed for 1,000,000,000 content bytes, but validation **failed** after 10.268 seconds externally observed, at 324,976,640 bytes native peak RSS: `BUDGET_EXCEEDED: review bounded capture exhausted`. The baseline review verifier applied its 4,096-document capture limit before determining whether a review was involved. The experiment's time, memory and disk limits were not exceeded, and fixture/source hashes were unchanged. This is a product failure, not a passing scale result; the failed run and original binary are retained.

The repair checks review applicability using the same canonical-path and Markdown-fence parsers as receipt verification. Inputs without a review fence or retained witness avoid review-specific capture limits. Canonical malformed/wrong-kind receipts, encoded fences, deleted baseline receipts and retained witnesses still enter the existing checks; captured source text cannot become receipt authority. Genuine review captures still have their 4,096-file/64 MiB ceiling, so scaling those operations remains separate work.

The affected graph-review, eligibility, source, decision and inverse suites passed **91 tests**, with formatting and Clippy passing. The first run exposed two incorrect expected error codes in one new malformed-JSON test; the existing `ExtractionInvalid` behavior was preserved, the assertions corrected, and all 27 review tests rerun successfully. The original failure is retained. Independent review rated this bugfix **9/10 with no blockers**, without awarding capacity or semantic acceptance.

Both tiers then passed a newly frozen, read-only replay on their original audited fixtures. The replay retained the same time, memory and disk ceilings; its disk admission counted the existing files plus a 256 MiB report reserve instead of forecasting another fixture copy. All four 1k commands and all three 10k commands passed, including pre/post fixture audits and unchanged source/binary/file pins. Every non-timing 1k validation/full-projection result field matched the original baseline.
