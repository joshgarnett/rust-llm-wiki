## Delivered boundary

- `paths.rs`: canonical root binding, exact-case regular `WIKI.md` explicit selection and nearest-ancestor discovery, pre-filesystem non-UTF-8 rejection, existing-component symlink/containment checking, Unicode-folded portable collisions against existing entries and every planned prefix. A supplied root symlink is rejected; ancestor system aliases are resolved once to the canonical binding (e.g. macOS temporary `/var` aliases). Hostile concurrent symlink substitution remains outside the initial contract.
- Deterministic bytewise Markdown envelope discovery skips symlinks, `.wiki`, `.git`, root `changes/**`, and generated `index.md`; only exact `sources/<id>/revisions/<rev>/revision.md` is discoverable under a revision. Original/content payloads, including Markdown with forged frontmatter, are excluded.
- `lock.rs`: persistent writer-lock inode, real `std::fs::File::try_lock` authority, bounded contention and retryable `CONTENT_CONFLICT`; private RAII `WriterPermit` binds the canonical vault. PID text has no authority. Bootstrap created state directories and their parents are synced via `NativeIo`; the lock is never unlinked.
- `fs.rs`: same-directory exclusive stages, staged-byte hash verification, fsync before replacement, final expected-hash/absence guard immediately before rename or removal, directory sync result, exact before-images exposed for P03 retention. Wrong-root permits are rejected. Proposed hash is private with getter. Newly created managed directories and parents are synced.
- `DurableIo` wraps actual create/write/file-sync/rename/remove/directory-create/directory-sync/append-open/truncate operations. Fault fixtures call `NativeIo` through this production adapter, injecting before and after each real boundary. P03 received root-bound `append_synced`, `truncate_synced`, and `sync_target`; append/truncate are restricted to `.wiki/state/**`. No journal state machine was implemented here.

Root registered the module surfaces and verified/pinned `unicase = 2.9.0`; its modern Unicode table replaces the initially proposed Unicode-9 `unicode-casefold`. Regressions cover Straße/STRASSE and Georgian Mkhedruli/Mtavruli collisions.

## Limits and follow-up

These are current-process real filesystem/fault/lock tests, not power-loss durability qualification. Errors after rename/delete leave the proposed state available for P03 recovery; P03 must retain payloads and journal intent before invoking mutations, then resync observed target/parent before completion. Individual successful replacements were tested on current macOS; no multi-file atomicity or external-editor compare-and-swap is claimed. An editor can modify the destination after the final hash check; before-images preserve observed bytes only. `NativeIo` reports directory sync unsupported on non-Unix targets rather than claiming durability; root-level policy must handle that result. Windows/Linux native replacement, locking, filesystem-entry, and crash/power-loss qualification remains unrun. No paid/network/GUI/host tests apply to this package.

## Independent review corrections (2026-09-28)

The Astra review reproduced two deficiencies, recorded in `P02-review.md`. Both corrected within the renewed lease; acceptance remains root/reviewer-owned:

- R1: `ensure_directory` previously returned success for an existing directory without resyncing its entry after an interrupted mkdir. It now syncs every traversed directory and parent after either mkdir success or an accepted existing-directory state. `interrupted_directory_creation_retry_resyncs_every_directory_and_parent` injects failure after native mkdir and before/after directory sync, then proves successful retries perform four actual `NativeIo` directory sync calls for a two-prefix path. A subsequent fully existing-directory retry repeats those four calls. Unsupported/error results propagate.
- R2: parent scans previously included child vault records. An exact-case regular child `WIKI.md` now establishes a subtree exclusion; `resolve` also rejects any descendant directory bearing this marker so parent managed reads/writes cannot cross the vault boundary. `nested_vaults_are_separate_scan_and_managed_path_scopes` proves scan isolation, parent existing/new-target refusal, valid explicit/discovered child operations, and consistent lowercase/symlink marker treatment.
