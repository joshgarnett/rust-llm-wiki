## R1 — high: durable send authority loses its closing clock/rate proof

`src/jobs/ledger.rs:1703` checks rate validity before and after the durable SendAuthorized append, but `authority_gate` (`:372`) discards its successful final `ClockReading`. `src/jobs/types.rs:707` stores only attempt/bound/event/genesis. Dispatcher `src/providers/dispatcher.rs:231` compares a later clock reading to the older attempt-start reading and discards the result. Native `src/providers/transport.rs:77` starts a new Timer baseline. Its final preflight (`:245`) checks credential/trust and deadline, but never checks the rate card again.

Two concrete gaps follow. First, a DispatchLocked rate can expire after begin_send's closing flush and before the first HTTP future poll. EntireAttempt pricing can also cease to cover `now + timeout` even before the card itself expires. Second, a clock can regress below the ledger's closing reading while remaining above credential acquisition and the attempt-start reading; Timer accepts the lower reading as its fresh baseline. Neither the opaque one-use token nor credential TTL closes these gaps.

Root-owned closure proposal:

1. Return the successful final reading from `authority_gate`. Mint SendAuthorization with that private reading, its original authoritative `Arc<dyn JobClock>`, cancellation binding, effective deadline, and effective limit snapshot (or an equally strong prederived temporal proof). Keep existing bound/event/genesis binding and non-Clone/non-Deserialize construction.
2. Add a crate-private mutable pre-entry method that samples that owned clock; rejects UTC/monotonic regression against its latest reading, invalid UTC, cancellation and deadline; repeats `budgets::quote_bound` against the exact bound/effective limits/deadline; and advances its latest reading. Preserve any newer post-begin_send dispatcher reading through this method instead of discarding it. No public caller-supplied clock or replacement proof.
3. Initialize Native Timer from the latest sealed sample, preserving continuity. After pure client/request building, perform final trust/credential checks and then the accounting check inside the first actual HTTP poll wrapper, immediately before `entered = true; sending.poll(cx)`. Alternatively prove that no await can intervene between those checks and the first poll. Current `bounded` uses select and can choose its timer branch before polling HTTP, so an outside-only check is insufficient. Check cancellation again after the final clock read, since injected clock behavior can cancel during sampling.
4. Apply this rate admission only before first entry. After entry, DispatchLocked expiry cannot retroactively become not-sent. Existing conservative entered failures and accounting remain required. No new durable authority event/schema is necessary; no ledger lock should be held over network.

Required focused runtime evidence: native server count zero after delaying first poll across DispatchLocked expiry, across EntireAttempt coverage exhaustion, and after UTC/monotonic regression below the closing sample but above credential acquisition. Verify durable ReleasedNotSent/reopen after native refusal, plus unknown charge retention when the same changes occur after entry. Existing final-guard lease/config/cancel tests do not demonstrate these cases.

## HTTP parser backing argument

Locally inspected pinned Hyper1.11.1 `proto/h1/io.rs:175,224`, `role.rs:1086,1184`, and bytes1.12.1 `bytes_mut.rs:626` agree with the report's core mechanism: complete headers precede the partial-parser threshold; IO exposes all BytesMut spare capacity; informational header slices/maps drop before another reserve when no informational callback retains them. Native transport installs no such callback and no pooling.

For unique backing capacity C, consumed offset O, live length L<M, and requested additional R≤M−L: growth is unnecessary when C≥2M. If O≥L, reclamation has enough capacity; if O<L, O+L+R<2M≤C. Thus an actual grow starts with C<2M, needs O+L+R<3M (O≤C), and max(doubled C, required)<4M. With M=417792 this gives 1671168 logical bytes. bytes' unique ARC and Vec branches follow this reasoning. The final Vec growth bound still depends on the pinned Rust RawVec behavior cited in P16b.md; installed rust-src was unavailable and network was prohibited for this review, so that final dependency was not independently reopened here.

The regression `src/providers/dispatch_tests.rs:917` checks exposed capacity, not backing capacity C after a consumed offset. Its adversarial pipelined case exercises the previously missed growth path, but output must continue to say “modeled exposed capacity”; it does not measure allocator RSS, transient realloc overlap, header-name/HeaderMap allocations, or body storage. The written proof establishes the backing bound conditional on pinned RawVec. Retained normal header limits are separate postparse limits. Repeated informational TCP behavior is a distinct integration check, not allocator instrumentation. Reported private19/public4 runs are worker evidence; later added native cases were unrun in the report read here.

### Final-send continuity follow-up: live Timer floor must reach the seal

The later transport now starts Timer from the sealed closing sample and invokes the seal immediately before actual HTTP poll. Root's additional counterexample is confirmed against that source: `bounded` (`transport.rs:118`) advances Timer.last to T+200, but final `authorization.check_before_entry` (`:282`) compares its owned T+150 sample only to an older T+100 sealed reading (`jobs/types.rs:748`). It can enter HTTP before a later check notices regression. Capturing timer.last before calling bounded does not solve this because bounded can repeatedly advance the timer while waiting.

The private floor-aware method should compare the owned clock to the componentwise maximum of stored seal and live Timer.last. A caller floor can only tighten the proof; it neither supplies the final clock nor weakens the owned baseline. The first-poll callback needs the live mutable Timer. The smallest coherent refactor is a private `bounded_poll` helper whose callback receives `&mut Timer`; each select scopes that borrow so the outer loop can check on the next iteration. Ordinary bounded futures delegate to it. Native's callback rechecks trust/lease, then samples `check_before_entry_after(timer.last)`, passes that same reading to a clock-free Timer.observe method, and sets entered/polls immediately. Timer.observe retains final cancellation/deadline/elapsed/wall checks and updates last; no new clock read may intervene. This also prevents the reverse gap where a later Timer check forgets a newer successful final seal reading.

Concrete snippets and regression recipes are in `/tmp/lwiki-final-send-continuity-proposal.rs`. Count-free native regression: a real ledger/SendAuthorization uses a controlled owned clock closing at100, later150; a private context-clock wrapper over that clock returns200 to the real Timer; a valid unchanged credential lease remains available. Real NativeTransport must refuse with not_entered, zero observed bytes and zero server requests, then permit durable ReleasedNotSent/reopen. Old code sends because150≥100. Mirror the check with only monotonic time advancing. This tests the stricter Timer floor without native read-count assumptions; a strict same-Arc chronological sequence would need a cfg(test) boundary hook. A focused poll-sentinel check should additionally prove that a successful newer seal sample becomes Timer.last before the poll. These are static proposals only; no source edits, Cargo or runtime execution were performed in this follow-up. Report/proposal lease returned to root.
