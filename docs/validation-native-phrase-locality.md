# Native phrase-locality development comparison

The phrase-locality candidate **failed the unchanged quality gate and was not
promoted**. Actual returned evidence supports 11/28 facts and completes 2/10
positive tasks, compared with 9/28 facts and the same two complete tasks for the
accepted executable. Four baseline-supported facts are lost. Accepted production
retrieval remains unchanged.

## Hypothesis and frozen method

An independent architecture review admitted one candidate after a development
probe showed complementary restore-role evidence receiving no new unigram
coverage. The candidate adds original-adjacent query-token pairs to the existing
coverage features. A pair needs a complete byte witness in one original Markdown
structural block; grouping cannot invent adjacency, and clipping must retain the
whole witness. Stopword removal cannot create a new pair. Unobserved pairs leave
baseline behavior intact. Allocation, density, weights and output limits remain
unchanged. Pair coverage makes no claim about approval, truth or task completeness.

A fresh independent critic froze the exposed twelve-task protocol before seeing
outcomes: ten positives comprising 28 required facts, plus two absent controls.
Advancement required at least 24/28 facts, 8/10 complete positives including
D01/D09/D10, no original or fresh baseline fact loss, exact current citations,
both absent controls and bounded error-free execution.

Both arms used separate copies of the same 64-source canonical seed and immutable
source revisions. Their old derived catalogs required ordinary independent
normalized rebuilds, followed by complete checks. Twenty-four context commands
used identical lexical requests and alternating arm order:

```text
--path-prefix sources/ --limit 5 --candidates 80 --excerpt-bytes 1024
--max-bytes 6000 --max-tokens 1500 --no-sync --scope indexed-documents
--verification-max-entries 65536
```

This is the existing small-budget development profile. Actual CLI defaults are
ten owners, 12,000 bytes and 3,000 estimated tokens; they were not substituted for
this denominator. No unseen HIGH question, provider call or model job was used.

## Implementation validation and retained failures

The integrated batch has 87 distinct affected native checks passing: 61 unit
checks, 21 context integration checks and five skill-export checks. Checks cover
original-block locality, grouping, filtering, clipping, tokenizer behavior,
no-pair equivalence, qualified evidence and a public context/Source-refresh smoke.
An optimized native build took 112.313 Bazel seconds. After grouped fixture fixes,
the affected integration build took 58.657 seconds; its production executable
was byte-identical. Only the two failed checks were replayed, reusing 85 passes.

An initial copied-test launch lacked the Bazel runfiles environment and failed
before invoking the CLI. Correcting that launch exposed two fixture failures:
the new indexed-document test needed normalized activation, and the maintained
export manifest/command reference lagged already accepted runtime capabilities
and guidance. Both were corrected together. Those failures remain in local
evidence; passing mechanics did not override the failed quality comparison.

The candidate's two Rust paths were restored to accepted source in the isolated

The original unfinished main-tree work remains intact. Generated export references

## Decision

Stop phrase-weight, density and grouping retries. A fresh whole-workflow review
must choose a coherent user benefit and a discriminating experiment before another
uncertain implementation. Native default advancement, unseen HIGH, semantic
quality, complete 10K/25K lifecycle and whole-release acceptance remain open. The
separate [assisted answer/Page workflow](validation-assisted-answer-pages.md)
demonstrates existing task-aware selection and maintenance, with no comparative
credit for this native trial.
