# Bounded wiki workflows

Choose only commands advertised by the running release's `capabilities`; inspect `schema NAME` for machine inputs. `references/commands.md` is generated at export and includes actual argument help. Examples use `--offline --json --wiki DIR` with a disposable `WIKI.md` vault; ordinary use selects the user's intended existing vault. Never initialize over an existing vault.

For a literal identifier, use `search IDENTIFIER --mode literal --limit 5 --excerpt-bytes 240`. For a paraphrase, use lexical search and inspect returned citations; lexical matches alone do not establish a claim. Use `context QUERY --max-bytes 12000 --max-tokens 3000` to assemble bounded context, reserving instruction/output space when needed. For a relationship use `graph query QUERY --strategy relationship` or `context QUERY --target graph --strategy relationship`. Follow evidence IDs with `read --id ID`, using byte ranges and `--max-bytes` when appropriate. Citations bind exact source revisions and quotations; a current heading is not their identity.

Capture a local file with `source add FILE --title TITLE`. Retain its source and immutable revision IDs. Repeated identical input may reuse captured immutable content; inspect returned IDs and never promise whole-source identity deduplication. Withdrawal uses `source withdraw SOURCE_ID --reason REASON`; it makes that source unavailable for Current support. Historical records remain preserved. Refresh creates a new immutable head; old evidence needs explicit `evidence revalidate` and subsequent review where required.

For authorized extraction, export `graph extract --executor agent --source-id SOURCE_ID`, preferably with explicit `--window START:END` and mention/assertion/output bounds. Read the returned packet and extraction schema. Produce only packet-bound JSON, using exact UTF-8 spans/quotations and window IDs. Keep uncertain mentions unresolved and retain conflicting assertions. Do not infer entity identity or add an accepted flag.

Stage `graph import --file RESPONSE.json`, inspect `changes show CHANGE_ID`, then `changes apply CHANGE_ID`. Materialization is required before resolution; there is no implicit staged overlay. Read the extraction record to obtain its current hash. Use `graph resolve --file RESOLUTION.json` with explicit mention mappings and expected hashes. Inspect/apply that change. Use `graph decide` only for explicit identity/alias decisions with complete guarded references and remaps; matching names are insufficient.

Review every active evidence item using `graph review --file REVIEW.json`; the review schema requires current assertion/evidence hashes, reasons and assessments. Read and assess the cited passages before accepting. Apply the reviewed change after inspection. Proposed assertions, unresolved identities, retracted support and unsupported claims must remain distinguishable. Repeating a packet-bound import reuses its retained origin rather than creating another assertion set.

`page put --file FILE --path PATH --if-match HASH` preserves author edits by guarding the current bytes. Heading changes keep `wiki_id`; relocation uses `page rename ID --to PATH --if-match HASH`. A stale hash conflict means reread the changed page and reconcile the intended edit; do not substitute a new hash and replay blind. `--dry-run` reports planned effects without writes; it cannot establish fresh index state. Inspect error codes and partial metadata. A reservation larger than the context ceiling is invalid (`USAGE`). Even a valid reservation can leave too little room for an unverified snapshot scope header (`BUDGET_EXCEEDED`), while Current scope can return empty partial context with omissions; do not retry by silently increasing the user's bound.

The examples JSON is an ordered recipe: each `args` array is passed literally to `lwiki`; `${name}` substitutes a previous output binding, `stdin` supplies local data/JSON and `bindings` map names to envelope JSON pointers. `expect_error` identifies a deliberate stopping case. The fixture-only `fixture_edit` appends a simulated external author edit in the disposable vault; never execute it against user data. Dynamic IDs/hashes must come from the actual previous command, never invented values. The packaging test executes these same maintained steps plus citation/identity and author-conflict assertions. It uses disposable fixtures and exercises actual review/apply; host GUI invocation and provider compatibility need separate qualification.

For a configured generation API, `graph extract --executor api --source-id SOURCE_ID --profile PROFILE --providers-config FILE --max-requests N` uses the same packet-bound import pipeline. It stages proposals and preserves explicit decisions; it does not accept extracted assertions. `embeddings check` reports local coverage; an explicitly authorized `embeddings sync` makes accounted remote embedding requests. Read the running command reference for the exact supported bounds and configuration options. Static/dynamic secrets belong to trusted private configuration outside the vault; never copy them into Markdown or model input.

For standalone research, preview `research plan QUESTION --url URL` with scope exclusions, source/round limits and request bounds. A preview grants no provider trust and makes no paid call. An explicitly authorized `research run QUESTION --profile PROFILE --providers-config FILE --url URL --max-requests N` uses generation and bounded public acquisition; `--search-profile PROFILE` opts into configured discovery. Local-source research can omit URLs. Ordinary mode stages proposed page changes; `--apply` explicitly permits guarded page application. Model output cannot raise budgets, choose arbitrary paths, dispatch hidden work or accept assertions.

Keep the actual run ID. `research status RUN_ID` and `research report RUN_ID` read retained local state without credentials. Budget exit 7 and interruption exit 130 carry a durable partial research outcome in the error details; inspect its passages, gaps and prepared changes. A partial report may contain valid quoted evidence alongside unanswered questions and unassessed model claims. `research resume RUN_ID --providers-config FILE` preserves prior work and lifetime accounting. Changed sources/services require revalidation, while unknown in-flight paid attempts require reconciliation before new dispatch. Never promise that an interrupted request was free.

To explicitly amend a paused/stopped run, provide `--amend-limits FILE`: a bounded JSON object with `limits` (the complete LifetimeLimits object), `deadline_utc_ms` (absolute UTC milliseconds) and a nonempty `reason`. Start from the retained effective limits/deadline returned by status, change only explicitly authorized bounds, and keep any raised values monotone. The amendment is recorded; it neither erases requests/holds nor resets round/source counters. Dry/offline resume only previews retained work and the requested amendment. Do not substitute the initial-run budget flags on resume; they are rejected.
